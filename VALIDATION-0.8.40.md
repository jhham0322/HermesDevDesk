# 0.8.40 browser cancellation and safe state persistence

Baseline: published v0.8.39 commit 87bd367b65e4b37dd61266e2759b5825ec4d705e. Prior diagnostic branches are preserved; their command-startup instrumentation and comparison experiments are excluded from this release branch. No user changes were present at the initial checkpoint. Prior tags/assets remain immutable.

BrowserAction's 35-second CancellationTokenSource deadline is removed. Linked caller cancellation and the existing execution-stop lifecycle cancel active and queued requests. Tab removal and browser disposal cancel their associated requests; another chat is preserved. Queue cancellation only releases a semaphore actually acquired. Explicit cancellation and genuine navigation timeout have separate messages. The existing navigation 20-second and host-response 40-second guards remain unchanged. Existing busy-tab and approval/restart guards remain.

StateStore instances share a lock by full state-file path and Load permits file replacement. Each save flushes a unique staging snapshot; backup replacement is staged too. Sharing/access conflicts retry at most three times with 40/80/160ms delays. A read-only target or directory conflict is not overridden. Failed replacement keeps the original and the complete new pending snapshot for manual recovery. No ACL, elevated access, attribute reset or implicit restore of user data is performed. Actual incident path/ACL/lock owner is not available, so these fixes do not claim that all permission failures disappear.

Owned Windows regressions cover short/permanent file-reader locks, read-only preservation, directory conflict, legacy staging preservation, two independent stores saving concurrently, valid/invalid URLs and explicit resume/unknown-side-effect guards. Existing 431 plus 23 new assertions reach 454 checks. Dedicated real WebView2 checks cover pending beyond 35 seconds, Stop response, caller and queue cancellation, other-chat isolation, tab/application disposal and retained navigation timeout. Initial test setup waited on a hidden WebView before entering the test; that fixture was corrected and its owned stalled process was cleaned up without touching user applications. Synthetic running tasks are stopped before smoke-test shutdown so the real running-work exit confirmation remains intact.

ErrorHttpInvalidServerResponse is the documented WebView2 invalid/unrecognized server response enum. Actual URL/server cause remains unconfirmed. Userinfo/scheme validation and certificate validation are unchanged. No real company requests are made by these checks. Local artifacts and exact commit/package/download evidence are kept under ignored artifacts. Publish only verified EXE/ZIP to the existing public jhham0322/HermesDevDesk Releases; never commit package binaries or publish user profiles/logs.
